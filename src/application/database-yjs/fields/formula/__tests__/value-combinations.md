# Concrete Formula value coverage

`value-combination-dataset.json` is the same authored input/expected-value dataset used by the desktop suite. It contains **26 result contracts and 187 concrete contract/value states across all 20 database field types**. Formula contracts cover text, number, boolean, date, and list results; Rollup contracts cover numeric Sum, numeric Percent checked, and original lists from actual related Formula fields.

The finite matrix includes self combinations and both/all operand orders:

| Coverage | Executed combinations |
| --- | ---: |
| Ordered contract pairs | 676 |
| Ordered concrete value pairs | 34,905 |
| Ordered contract triples | 17,576 |
| Ordered concrete value triples | 6,503,827 |
| Compatible pair values through six typed IF/IFS/ternary branches | 52,350 |
| Incompatible pair branch compilations required to fail | 3,120 |
| Binary operators (14 plus 2 logical aliases) over all value pairs | 558,480 |
| Unary negation and both NOT spellings | 561 |

Exactly 64 pair assignments and 35,376 triple assignments are impossible because the same row cannot have different values for one shared Created time, Last edited time, Created by, or Last edited by metadata key. They are explicitly counted and excluded. No ordinary field self combinations, reversals, missing cells, or zero values are excluded.

## Inputs and independent expectations

Concrete states include absent and blank cells, whitespace, zero and negative zero, negative and fractional numbers, a small fraction, the largest safe integer, malformed numbers, Unicode and multiline text, duplicate select labels, multivalue lists in both orders, duplicate values, empty titles, anonymous/missing members, checklist fractions, parsed durations, date ranges, the Unix epoch, a pre-epoch date, hidden times, and daylight-saving boundary instants.

Expected raw types, values, normalized text, predicate truth, and Formula `empty()` behavior are authored in the dataset. Four-row and eight-row Boolean tables are independently specified in the tests. Expectations are never generated by another Formula evaluation. Numeric zero remains a number even though `empty(0)` is true. A Sum over only empty Formula results is Empty; a Sum over an actual numeric zero is numeric zero.

`value-combination-fixture.ts` encodes only the input records into real Yjs database fields and rows. Related title/member lookups use the fixture's input records. Rollups call the production evaluator over separate related database/row YDocs and actual Formula targets. Their results are computed once per immutable graph and then reused; no expected Rollup answer is injected. All 187 states are additionally checked in each of three field positions against original documents and fresh documents reconstructed with `Y.encodeStateAsUpdate` / `Y.applyUpdate`, including recomputed Rollups.

## Formula combinations

`value-combinations.test.ts` checks every pair/triple's actual normalized payloads as well as AND/OR/NOT, grouped Boolean expressions, priority IFS, nested IF, and ternary outcomes. Each tuple reads its prebuilt YRows through production field adapters, sharing reads only within that tuple. Compiled expression trees are reused for a fixed contract tuple, which keeps millions of evaluations practical without sampling values.

Every tuple carries a guarded raw typed operand through a downstream Formula. Compatible pairs additionally select both source operands with IF, IFS, and ternary expressions, including inverted predicates, and preserve their raw number/date/boolean/list/text results through two Formula references. Incompatible typed branches must fail compilation. Failures identify contract IDs and concrete value IDs; final guards assert all executed and excluded counts.

This exhausts the documented finite dataset and expression templates. It does not claim to enumerate arbitrary Formula programs or all possible user values.

`value-combination-operators.test.ts` checks every binary operator against every
realizable ordered value pair, including expected static type rejections, and
all three unary forms against every value. Integer results are exact;
fractional arithmetic has a narrow relative tolerance. Text ordering and date
format expectations are explicit, independent tables. Raw date assertions
preserve the authored time-display flag as well as start/end timestamps.

## Researched Campaign Average workflow

`campaign-formula-rollup-values.test.ts` adapts the [Airtable campaign Rollup example](https://support.airtable.com/articles/7497685062-rollup-field-overview). Source Formula rates are independently specified as 20%, 40%, 0%, and Empty (nothing sent). All 16 relation subsets run through the actual Average Rollup and a downstream Formula, before and after Yjs serialization. A real 0% rate participates in the denominator; an Empty rate does not.

The [research scenarios](researched-scenarios.md) document primary sources and
all **1,056** business input products: deadlines (16), RICE scores and voter
lists (768), invoice totals and payment state (256), campaign subsets (16).
`researched-business-scenarios.test.ts` covers the first three through stored
Yjs cells and Formula references with independent expected results.

## Run

```bash
TZ=UTC npx jest src/application/database-yjs/fields/formula/__tests__/value-combinations.test.ts src/application/database-yjs/fields/formula/__tests__/campaign-formula-rollup-values.test.ts src/application/database-yjs/fields/formula/__tests__/value-combination-operators.test.ts src/application/database-yjs/fields/formula/__tests__/researched-business-scenarios.test.ts --runInBand --no-coverage
```

These unit suites need no application server, backend, browser, or feature flag. Pair/triple loops are grouped by their first contract; exact loop counts, rather than the smaller number of Jest test declarations, define coverage.

Verified locally: all 80 matrix test groups passed in 156 seconds, including the final exact coverage guards; all 17 Campaign tests passed. Targeted TypeScript and ESLint checks also passed. The initial all-empty Sum expectation was corrected only after both the desktop backend and the web evaluator independently demonstrated Empty, preserving the separate real-zero case.
