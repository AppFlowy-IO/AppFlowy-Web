# mention-eval

The client ranker replay and TypeScript/Dart parity gate of the @-mention plan (MEN-X-07): seeded
sessions of one synthetic workspace, the rankings the client ranker with pick memory gives for every
prefix the user typed, and the verdict of the gates that decide whether `mentionTypeaheadV2` and pick
memory may default on.

AppFlowy-Web keeps the canonical copy in
`src/components/editor/components/panels/mention-panel/__fixtures__/mention-eval/` and writes it with
`scripts/mention-eval/run-eval.mjs`. AppFlowy Desktop keeps a byte-identical copy in
`frontend/resources/mention-eval/` and replays the same sessions through its Dart ranker. Both
repositories check the same `FIXTURES.sha256`. This folder is apart from `mention-parity/` (the
typeahead contract's vectors, canonical in AppFlowy-Cloud-Premium), whose manifest it leaves alone.

## Files

| File | Contents |
| --- | --- |
| `sessions.json` | The generator's parameters, the workspace (`views`, `people`, `requester`) and two event lists, `events` and `probes`. Generated: do not edit. |
| `expected-rankings.json` | `sessions_sha256`, `top` (8) and `cases`: `[pick, prefix, ids]` for every replayed prefix of every pick of `events`, then of `probes`, with the client ranker's best ids. Generated. |
| `verdict.json` | The gates over the `events` cases and the integer counts of every arm, by prefix bucket, lane and script; the probes' counts apart. Generated. |
| `README.md` | This file. |
| `FIXTURES.sha256` | The manifest. Never edit it by hand. |

## Commands (AppFlowy-Web)

```sh
pnpm mention:eval                                    # check: fails when a file here is stale
node scripts/mention-eval/run-eval.mjs --write       # rewrite the generated files and the manifest
node scripts/mention-eval/run-eval.mjs --write --copy-to <AppFlowy-Premium>/frontend/resources/mention-eval
node scripts/mention-eval/run-eval.mjs --report /tmp/mention-eval-report.json   # examples where arms disagree
```

`--check` fails on a stale file, and on a failing gate only while `MENTION_TYPEAHEAD_V2_DEFAULT` or
`MENTION_PICK_MEMORY_DEFAULT` is on (or with `--require-gate`). A change to the ranker, the pick
memory, the normalizer or the generator changes these files: run `--write`, commit the folder, and
copy it byte for byte to Desktop in the same change, whose Dart test must then pass.

## Sessions

One workspace and 30 days of one user, generated by `scripts/mention-eval/sessions.ts` from the
parameters `sessions.json` records under `generator.params`. The parameters of the events were fixed
before any ranker was replayed and must not be tuned to a result: the replay is a regression guard
for the client rankers, not a measure of their quality, which online session metrics (MEN-CLOUD-05,
MEN-WEB-04, MEN-DESK-10) decide. The probes, which no gate reads, got their five same-day picks after
the first replay showed that no case reached the one-tier lift.

- 2,000 pages and databases (185 databases), 150 of them created during the 30 days, including 30
  pages titled `Meeting notes`, a roadmap family, diacritics typed with and without accents, letters
  the contract does not fold (decision D1), Greek capitals ending in a final sigma, Han, kana and
  Hangul titles, emoji, and titles past 128 and 512 code points.
- 200 people on one address domain, the requester first; Greek, Han, kana and Hangul names, and four
  blank names shown by their address.
- `events`: 2,400 opens, 150 creations and 600 picks, at random minutes from 09:00 to 18:00 UTC,
  workdays six times as likely as weekend days. Opens and page picks choose a view by Zipf weight
  `floor(2^24 / rank)` over a seeded order; a view created during the replay is as popular as the
  eighth for two days. Half the picks are of a person, by the same Zipf weights over a seeded order
  of people. A pick's query is one of its target's habitual forms (a title or name prefix, the whole
  title, a later word's start, two word starts, a piece of a long word, or the forms the catalog
  writes out), the first seven times in ten.
- `probes`: seven picks of each of the 107 targets whose forms the catalog writes out or whose title
  is longer than 128 code points: the first form five times an hour apart from a random time (the
  fourth same-day pick earns the one-tier lift, which the fifth ranks with), the second form two days
  later and the third an hour after that, and an open of a view five minutes after its first pick.
  The behavior rarely reaches these targets or the lift, and they carry the traps the parity check
  needs. They never weigh on the gates.

Times are integer milliseconds, rising strictly through each list; a view exists from its
`created_ms` on, and every view created during the replay has a `create` event at that time.

## Replay

Both ports replay the sessions by these rules, the TypeScript one in `scripts/mention-eval/replay.ts`
(AppFlowy-Web) and the Dart one in
`frontend/appflowy_flutter/test/unit_test/mention_person/mention_eval_replay.dart` (AppFlowy-Premium),
each with its client's production ranker and pick memory, never a copy.

1. `events`, then `probes`, are each replayed from an empty state: no last use, and an empty pick
   memory as the picker keeps it (the contract's 1,000 entries; an input that normalizes to more than
   32 code points is not recorded). Picks are numbered from 0 through `events`, then on through
   `probes`.
2. `open` and `create` set the view's last use to the event's time.
3. A `pick` `[t, "pick", id, typed]` is ranked in its target's section: People for a person (every
   person, in roster order), Pages or Databases by the view's kind (every view of that kind whose
   `created_ms` is at most `t`, in file order).
4. Its prefixes are the first 1, 2, ... code points of `typed`; a prefix whose normalized form (the
   contract's normalizer) is empty, or equal to the previous replayed prefix's, is skipped.
5. Each prefix is ranked by the contract's client ranking (`rankSection` on Web,
   `rankMentionSection` on Desktop) with its lane (people or objects), the clock `t`, a limit of 8,
   and these candidates: the key, the title or name, the address for a person, `adaptive` and `lift`
   from the pick memory's scores for the prefix at `t`, the last use as `lastUsedMs` (none when
   never used), `requester` for the requester, nothing present, and no server rank (the local lane).
   The ids of the result, best first, are the case's ranking.
6. Then the pick memory records `typed` for the target's key at `t`, and a person's last use becomes
   `t`. A page's or database's last use comes only from opens and creations, as on Web.

The TypeScript replay also ranks three baselines, graded but not recorded:

- the same ranking without pick memory (pick memory is off by default);
- MRU: the candidates used before (opened, created, or for people mentioned) whose title matches at
  T0 to T2, or people of class C0, the most recent first, then by key in code point order, as
  MEN-X-04's server baseline orders them;
- today's substring filter: the prefix trimmed and lowercased by JavaScript, then the titles, or a
  person's name or address, that contain it, in file order (Web's local fallback and Desktop's
  roster filter, which matches every address on a shared domain).

## Metrics and gates

Each case's target rank in each arm's best eight gives hit@1, hit@3 and its reciprocal rank (0 when
the target is not among the eight: MRR@8), counted per prefix bucket of the normalized prefix's code
points (`1`, `2`, `3`, `4-6`, `7+`), per lane (people, objects) and per script (`cjk` when the
normalized prefix holds a Han, kana or Hangul code point, else `latin`). Reciprocal ranks are summed
in units of 1/840, the least common multiple of 1 to 8, so `verdict.json` holds integers and every
comparison is exact. Only the `events` cases are graded.

The gates (the plan's Done-when):

1. `mrr_at_least_mru`: in every prefix bucket, the ranker's MRR@8 is at least MRU's.
2. `unique_exact_title_hit_at_1`: a page or database whose title the prefix matches exactly (T0),
   when no other candidate's title does, is the ranker's first (MEN-X-04's ship gate; 30
   `Meeting notes` pages cannot all be first, so a shared exact title is reported apart).
3. `no_t0_t1_title_below_t3_t4`: over the ranker's whole order, no title of tier T0 or T1 comes after
   a T3 or T4 title. The local lane has no T4 item (an unmatched server item), so T3 decides here.
4. Identical rankings in Dart and TypeScript: Desktop's `mention_eval_parity_test.dart` replays the
   sessions and asserts every case of `expected-rankings.json`.

If a gate fails, the ranker, the generator and the gates are not tuned to pass it: the failure, its
cases and its likely cause are reported, and the switches stay off.

## Determinism

- The generator draws from mulberry32 with exact integer steps; weights, times and counts are
  integers; no wall clock, locale or floating point.
- The rankers' comparators are total (the navigation key in code point order breaks every tie), so
  Dart's unstable sort and JavaScript's stable sort agree.
- Pick memory is integer arithmetic in millionths that decays per whole day (contract D12).
- Text follows the contract's normalizer: per code point lowercase, an explicit White_Space class,
  code point lengths.

## Byte rules and manifest

- ASCII only: every character above U+007E in a JSON string is a `\u` escape, so no editor can change
  a title. LF line endings, no BOM, exactly one trailing newline, JSON indented with multiples of two
  spaces.
- Every repository marks this folder `text eol=lf` in `.gitattributes`.
- `FIXTURES.sha256` lists the SHA-256 of every file here except itself, sorted by path in byte order,
  under a one-line header. `run-eval.mjs --write` writes it; this command gives the same bytes:

```sh
{ echo '# mention-eval v1: sha256 of every file here except this one, LC_ALL=C path order. Regenerate: see README.md'; \
  find . -type f ! -name FIXTURES.sha256 | sed 's|^\./||' | LC_ALL=C sort | xargs shasum -a 256; } > FIXTURES.sha256
```
