# Document import fixtures

`feature_matrix.pdf` and `feature_matrix.docx` are the same six-page acceptance documents
generated by AppFlowy Cloud Premium's `script/generate_document_import_fixtures.py` on the
document-file-import branch (PR #1240), extending the initial fixtures from commit `5b43d843`.
They contain a clickable contents index and return links, heading levels, formatted text,
external links, deeper lists, three tables (simple, merged and multiline), three-line code,
inline code, a diagram and a final-page sentinel. Typography samples include underline,
highlight, colour, double strike, superscript/subscript and paragraph alignment.

SHA-256:

- PDF: `3a6be2a0b4fde2501cc5784ea9be8463f0e84530b3183e495332c272642acf69`
- DOCX: `c92f91df3018736ffb92c1e1ee475b69331a90c3af47199523f8c408fb68b3c5`

Run against a web app connected to a running Cloud, Worker, PostgreSQL and object storage:

```sh
pnpm exec bddgen test -c playwright.bdd.config.ts
pnpm exec playwright test -c playwright.bdd.config.ts --grep @document-file-import --workers=1
```

The scenarios create independent test accounts using the existing GoTrue test configuration.
For a local existing account, set `DOCUMENT_IMPORT_EMAIL` and `DOCUMENT_IMPORT_PASSWORD`.
Set `DOCUMENT_IMPORT_KEEP_PAGES=1` to retain the two imported pages for manual inspection;
otherwise the scenarios delete only the pages they imported. Terminal task responses and
screenshots are attached to the Playwright results. There are no import API mocks.

The separate `@document-import-storage-limit` scenarios use controlled quota responses at task
creation and during status polling. They verify the storage prompt and that the second selected
file is never uploaded. Real PostgreSQL quota rejection and safe error persistence are covered by
the server's `document_failure_reports_quota_code_and_sanitizes_internal_details` regression.

Both formats must render one native AppFlowy table of contents, with working clicks to
all six imported section headings, and preserve three-level list parents. Exactly one image must appear
between its section heading and caption, load at the source dimensions (960 × 240), and
match every RGBA channel of `feature_matrix.png`. That reference PNG is the original image
embedded in both fixtures, not a screenshot captured from the importer. All checks run
again after a reload and sidebar reopen. Missing images and substituted placeholders fail.

`feature_matrix.content.json` is the source-reviewed prose inventory shared with the
server tests. Every passage, including the source title and all ten column sentences,
must survive exactly once. It is independent of importer output. All cells in all three
tables are checked, including the visible text of the flattened merged table.

The browser also checks exact table dimensions/cell values, external link URLs, bold and
italic text, line breaks in code, Word cell emphasis/inline code and explicit heading levels.
Word's merged-cell warning is asserted. Colour, highlight, underline, alignment, merged
geometry and PDF table emphasis flatten; their text must survive. Neither format is expected
to preserve print pagination or running footers. Source PDF/Word navigation is also validated
by server tests; unrelated file-local return links remain plain text after importing.
